# ต้นแบบหน้าเว็บที่เหลือ + ปุ่มข้อเสนอแนะ — Design Spec

วันที่: 2026-10-19
โปรเจกต์: `acc-pharm-redesign/` · branch `feat/prototype-pages` (จาก `main`)
อ้างอิง: `docs/superpowers/specs/2026-10-14-redesign-design.md` (หลักการ UX ร่วม), `docs/superpowers/specs/2026-10-19-g-ux-foundation-design.md` (motion + guidelines), `docs/guidelines/web-interface-guidelines.md`

## เป้าหมาย

ทุกเมนูที่ยังเป็นหน้า "กำลังพัฒนา" กลายเป็นหน้าต้นแบบที่คลิกเล่นได้ เพื่อให้ทีมและ สรร. ลองใช้ครบทุก role แล้วส่งข้อเสนอแนะกลับมาผ่านปุ่มในหน้าเว็บ — ใช้เก็บ requirement ก่อนทำจริง

## ขอบเขต

- **ไม่แตะ** `src/lib/api.ts`, `src/lib/*Rules.ts`, เทสต์ และข้อมูลของ flow ที่ทำจริงแล้ว (F0–F4)
- ข้อมูลตัวอย่างอยู่ใน `src/mock/prototype/` (ไฟล์ต่อกลุ่มหน้า) — หน้าต้นแบบ import ตรงได้ (ข้อยกเว้นของกฎ "ผ่าน api.ts" เฉพาะหน้าต้นแบบ)
- การกดเล่นใช้ state ในหน้า (`useState`): ตัวกรอง, ค้นหา, modal เพิ่ม/แก้ไข/ลบ (มียืนยัน), ฟอร์มที่ตรวจความถูกต้องและแสดง error ใต้ช่อง, เปลี่ยนสถานะ, toast — **ไม่เก็บถาวร** รีเฟรชแล้วกลับเป็นข้อมูลเดิม
- ทุกหน้าต้นแบบมีป้าย "ต้นแบบ — ข้อมูลตัวอย่าง" ใต้หัวข้อหน้า (component `PrototypeBadge`)
- ใช้ของจากงาน G: component class ใน `globals.css`, `Field`/`inputClass`/`fieldAria`, `StatusBadge`, `Stepper`, `useFocusTrap`, `focusFirstError`, `useQueryState` (ตัวกรองหลักของหน้ารายการ), คลาส `animate-page`/`animate-stagger`/`animate-fade`
- ผ่าน Web Interface Guidelines เท่ากับหน้าที่ทำจริง; ภาษาไทยทั้งหมด; 375px และ 1280px ไม่มี scroll แนวนอน
- Dependency: ใช้ `animejs` (ติดตั้งแล้ว ^4.5.0) และเพิ่ม `recharts` (stack ของ Conference Backoffice) สำหรับรายงาน — ไม่เพิ่มอย่างอื่น

## 1. ปุ่มข้อเสนอแนะ (ทุกหน้า)

- Component `FeedbackButton` ใน `src/components/feedback/`; แสดงใน `AdminLayout` และหน้า public (`/login`, `/register`)
- ปุ่มลอยมุมขวาล่าง (`aria-label="ส่งข้อเสนอแนะ"`, มีจำนวนข้อเสนอแนะที่เก็บไว้) → modal (focus trap, Esc ปิด) มีช่อง:
  - ประเภท: ปัญหาการใช้งาน / อยากให้มีเพิ่ม / ข้อมูลไม่ถูกต้อง / อื่น ๆ (radio, บังคับ)
  - ข้อความ (บังคับ)
  - ชื่อผู้ให้ความเห็น (ไม่บังคับ — จำค่าล่าสุดไว้)
- แนบอัตโนมัติ: path + query ของหน้า, ชื่อหน้า (`document.title` หรือหัวข้อหน้า), role ของผู้ใช้ (หรือ "ยังไม่เข้าสู่ระบบ"), เวลาท้องถิ่น
- เก็บใน `localStorage` key `accpharm_feedback` (อยู่ข้ามแท็บ/รีเฟรช — เป็นข้อมูลของคนทดสอบ ไม่ใช่ข้อมูลระบบ)
- ใน modal มีแท็บ/ส่วน "ที่ส่งไว้ (n)" ดูรายการ ลบทีละรายการ (ยืนยัน) และปุ่ม **"ดาวน์โหลดทั้งหมด (.csv)"** — CSV คั่นด้วยจุลภาค ใส่ BOM `﻿` ให้ Excel เปิดภาษาไทยถูก คอลัมน์: เวลา, หน้า, path, role, ประเภท, ข้อความ, ชื่อ; escape เครื่องหมายคำพูดและขึ้นบรรทัดตามมาตรฐาน CSV
- บันทึกสำเร็จ → toast "บันทึกข้อเสนอแนะแล้ว ขอบคุณ"
- ฟังก์ชันแปลงเป็น CSV เป็น pure function ใน `src/components/feedback/csv.ts` และมีเทสต์ `node --test` 1 ไฟล์ (escape จุลภาค, คำพูด, ขึ้นบรรทัด, BOM) — ข้อยกเว้นเดียวของ "ไม่มีเทสต์ใหม่" เพราะเป็นข้อมูลที่ทีมต้องเอาไปใช้จริง

## 2. หน้าต้นแบบ

### F5a ตรวจรักษาคุณภาพ (ตาม design ที่ตกลงแล้ว — ข้อมูลอยู่ในหน้า)

- `/post-audit` รายการ: ค้นหา, chip สถานะ (รอตรวจ / รอแจ้งร้าน / รอร้านแก้ไข / ร้านแจ้งกลับแล้ว / ปิดแล้ว), ตัวกรองปี; admin มีปุ่ม "มอบหมายประจำปี"
- `/post-audit/assign` (admin): เลือกปี → ร้านที่ได้รับรองแล้วและยังไม่ถูกมอบหมาย (ค้นหา, กรองจังหวัด, เลือกหลายร้าน) → ผู้ตรวจ + วันนัด + วิธีตรวจ → ยืนยัน → toast แล้วกลับรายการ
- `/post-audit/[id]`: ส่วนหัว (ร้าน, ปี, ผู้ตรวจ, นัด, สถานะรวม, สถานะ 2 ส่วน) + tab ข้อมูล / ระบบร้านยาคุณภาพ / มาตรฐานบริการ / ประวัติ (`?tab=`); ในแต่ละส่วน: ผลตรวจ, timeline วงจร (ตรวจ → แจ้งร้าน → ร้านแจ้งกลับ → พิจารณา → ปิด), ปุ่ม action ตามสถานะและ role (แจ้งร้าน, ปิดผล, ให้แก้ไขเพิ่ม + เหตุผล), ร้านยาที่ "รอร้านแก้ไข" เห็นฟอร์มส่งการแก้ไข (ข้อความ + รูป 1–4 รูป)
- `/post-audit/[id]/inspect` (ผู้ตรวจ): stepper 3 ขั้น — (1) ระบบร้านยาคุณภาพ: 5 หมวด (สถานที่, อุปกรณ์, บุคลากร, การควบคุมคุณภาพยา, การปฏิบัติตามวิธีปฏิบัติทางเภสัชกรรมชุมชน) เพิ่มข้อที่ไม่เป็นไปตามมาตรฐาน + รูป + สรุป; (2) มาตรฐานบริการ Common illness: checklist 12 ข้อจาก `PostAudit.aspx` (ตรง/ไม่ตรง + ระบุเมื่อไม่ตรง), ความพึงพอใจ 5 ระดับ, สรุป; (3) ตรวจทาน + บันทึก
- เปิดสิทธิ์ `/post-audit` ให้ role ร้านยา (`rolePageAccess`) และเพิ่มเมนู "ผลตรวจรักษาคุณภาพ"
- animejs (ผ่าน hook `useAnime` ที่ข้ามไปสถานะสุดท้ายเมื่อ `prefers-reduced-motion: reduce`, ≤ 600ms, transform/opacity/stroke เท่านั้น): (1) timeline วงจร — เส้นวาดต่อทีละขั้นถึงขั้นปัจจุบัน + จุดปัจจุบันเด้งเบา; (2) วงแหวนสรุป checklist "ผ่าน n/12" — `stroke-dashoffset` + ตัวเลขนับขึ้น; (3) เครื่องหมายถูกวาดเส้นเมื่อปิดผลส่วนนั้น

### F5b ข้อร้องเรียน (admin)

- `/complaints` รายการ: ค้นหา, chip สถานะ (รับเรื่อง / แสวงหาข้อเท็จจริง / คณะอนุกรรมการ / คณะกรรมการสภาฯ / ดำเนินการตามมติ / ปิดแล้ว), ช่วงวันที่
- `/complaints/new` รับเรื่อง: ช่องทาง, ผู้ร้องเรียน (ชื่อ, ติดต่อ), ร้านที่ถูกร้องเรียน (ค้นหาจากรายชื่อ หรือระบุเอง), ผู้รับเรื่อง, มาตรฐานที่เกี่ยวข้อง, บริการ/โครงการ, ประเด็น, ระดับความรุนแรง, รายละเอียด, รูปหลักฐาน
- `/complaints/[id]`: ข้อมูลเรื่อง + timeline 15 ขั้นตาม `ComplainDetail.aspx` (ขั้นที่ผ่านแล้ว/ขั้นปัจจุบัน/ขั้นต่อไป, เส้นวาดด้วย animejs) + ปุ่ม "บันทึกขั้นถัดไป" เปิด modal ที่มีช่องของขั้นนั้น (วันที่ + รายละเอียด / ผลการพิจารณา / การดำเนินการ: ตักเตือน, สั่งหยุดบริการ + วันที่) + "ปิดเรื่อง"

### F6 ร้านยา

- `/pharmacies`: ค้นหา, กรองจังหวัด/สถานะใบรับรอง/ประเภท, ตาราง/การ์ด; สสจ. เห็นเฉพาะจังหวัดของตัวเอง
- `/pharmacies/[id]`: tab ข้อมูลร้าน / เภสัชกร / ประวัติการรับรอง / คำขอ / ตรวจรักษาคุณภาพ / ข้อร้องเรียน
- `/map` "ร้านยาตามพื้นที่": การ์ดภาค → จังหวัด พร้อมจำนวนร้านแยกสถานะใบรับรอง กดจังหวัดแล้วไป `/pharmacies?province=` (แผนที่จริงไว้ทีหลัง — ป้ายแจ้งในหน้า)
- `/gpp` (สสจ., superadmin): รายการผลประเมิน GPP ของร้านในจังหวัด, ปิดรอบประเมิน (ยืนยัน)

### F7 รายงาน

- `/reports`: เลือกประเภทรายงาน (คำขอตามสถานะ, ร้านยาตามจังหวัด, ใบรับรองใกล้หมดอายุ, ผลประเมิน GPP, ข้อร้องเรียน) + ช่วงวันที่ + จังหวัด → การ์ดสรุป + กราฟ (recharts) + ตาราง + ปุ่ม "ส่งออก Excel" (ต้นแบบ: toast อธิบายว่าจะได้ไฟล์อะไร)

### F8 ข่าว เอกสาร และงานผู้ดูแล

- `/news` รายการข่าว/ประกาศ (กรองหมวด) + `/news/[id]` อ่านข่าว; admin มีปุ่มเพิ่ม/แก้ไข (modal)
- `/documents` ระเบียบ/เอกสารดาวน์โหลด/คู่มือ (กรองหมวด, ปุ่มดาวน์โหลดเป็น toast); admin เพิ่ม/แก้ไข
- `/users` ผู้ใช้งาน: ค้นหา, กรอง role, modal เพิ่ม/แก้ไข (ชื่อ, username, อีเมล, role, หน่วยงาน, จังหวัดสำหรับ สสจ.), ปิดใช้งาน (ยืนยัน)
- `/master-data` ข้อมูลพื้นฐาน: tab ประเภทร้านยา / กลุ่มร้านยา / เครือข่าย (Chain) — รายการ + modal เพิ่ม/แก้ไข/ลบ
- `/templates` Template ข้อความตอบกลับ: รายการ + modal แก้ไข + ตัวอย่างข้อความ
- `/settings` (superadmin): ตั้งค่าระบบ — เกณฑ์ผ่าน GPP (%), อายุใบรับรอง (ปี), เปิด/ปิดรับคำขอ, อีเมลผู้ดูแล — บันทึกเป็น toast
- `/allocation` (superadmin) มอบหมายงาน: กำหนดจังหวัดที่ผู้ตรวจแต่ละคนรับผิดชอบ
- `/profile`: ข้อมูลส่วนตัว + เปลี่ยนรหัสผ่าน (ตรวจรูปแบบ, ไม่ส่งจริง)

เมื่อทุกเมนูมีหน้าแล้ว ลบ `src/app/[...slug]/page.tsx` (เส้นทางที่ไม่มีอยู่จริงใช้ 404 ของ Next)

## Definition of Done

1. `npm run lint` (0 warning), `npx tsc --noEmit`, `npm test` (เทสต์เดิม + เทสต์ CSV), `npm run format:check`, `npm run build` ผ่าน
2. ทุกเมนูใน Sidebar ของทุก role เปิดเป็นหน้าต้นแบบหรือหน้าจริง — ไม่มีหน้า "กำลังพัฒนา"
3. ทุกหน้ามีปุ่มข้อเสนอแนะ; ส่ง 2–3 ความเห็นจากหลายหน้า/role แล้วดาวน์โหลด CSV → เปิดใน Excel ภาษาไทยถูก คอลัมน์ครบ
4. แต่ละหน้าต้นแบบกดเล่นได้ตามที่ระบุ (ตัวกรอง, modal, ฟอร์ม + error ใต้ช่อง, toast) และมีป้าย "ต้นแบบ — ข้อมูลตัวอย่าง"
5. ใช้คีย์บอร์ดได้ครบ (modal กัน focus, Esc ปิด); reduced motion → animejs ไม่เล่น
6. 375px และ 1280px ไม่มี scroll แนวนอนทุกหน้า
7. ตรวจไฟล์ใหม่ตาม Web Interface Guidelines ไม่มีข้อค้าง
8. Merge เข้า `main` แล้ว push → https://acc-pharm-redesign.vercel.app ใช้ลองเล่นได้
